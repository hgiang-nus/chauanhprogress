# Châu Anh Progress — parent dashboard

A static dashboard for Châu Anh's parents, built from the tutors' class logs:
what was covered each week, how that matches the A-Level / IGCSE / SAT exams,
and the strengths, weaknesses and improvements the tutors reported.
Vietnamese by default, English toggle. Light and dark themes. Works on GitHub Pages.

```
chauanh-progress/
├── build.py               # reads the logs, writes docs/data/*.json
├── sources.json           # which log file belongs to which subject
├── curriculum_map.json    # syllabus units, keywords, indicative exam weights
├── observations.json      # strengths / weaknesses / improvements / gaps (hand-curated, bilingual)
├── logs/                  # the inputs
│   ├── Payment_Maths.xlsx         Phat  — A-Level Maths 9709
│   ├── Payment_Econs.xlsx         Duy   — IGCSE Economics 0455
│   ├── Payment_Business.xlsx      Business — same template, fill in as sessions happen
│   └── business_hub_index.html    copy of index.html from the "IGCSE Business: Road to A*" site
├── docs/                  # the website (GitHub Pages root)
│   ├── index.html
│   ├── assets/dashboard.css, dashboard.js, i18n.js
│   └── data/*.json        # generated by build.py — commit them
└── .github/workflows/build.yml   # rebuilds data on every push and every Monday
```

## Run it yourself

```bash
pip install openpyxl
python3 build.py                 # → docs/data/*.json
cd docs && python3 -m http.server 8000   # open http://localhost:8000
```
`build.py` prints every session with the syllabus unit it was mapped to and a
`WARNING` for any lesson title it could not map (fix by adding a keyword in
`curriculum_map.json` or an entry in `OVERRIDES` at the top of `build.py`).

## Publish on GitHub Pages

1. Push this folder to a repository (it can be a sub-folder of Châu Anh's existing
   site repo, e.g. `progress/`; then point the workflow's paths and the Pages
   source accordingly, or simply copy `docs/` into the site as `progress/`).
2. Settings → Pages → Deploy from a branch → `main` / `/docs` → Save.
3. The dashboard appears at `https://<username>.github.io/<repository>/`.
4. Weekly refresh: drop the latest `Payment_*.xlsx` into `logs/` and push.
   The workflow runs `build.py` and commits `docs/data/`. It also runs every
   Monday 08:00 Singapore time, so a log synced into the repo by any other
   means (Google Drive → GitHub sync, a manual upload) is picked up without a
   local build.

## Keeping it honest

- Only the **Class Log** sheet of each workbook is read; payment columns are never
  used. Rows need a `Date` and a `Lesson content`.
- `Feedback` cells longer than 60 characters are treated as tutor notes and
  copied to `docs/data/feedback_notes.json`. Read them when you update
  `observations.json`; the page never classifies a tutor's words by itself.
- Exam weights in `curriculum_map.json` are indicative (syllabus subtopic
  counts, recent past papers), and the page says so. For Economics and Business
  tick `subtopics_covered` as units are taught.
- Business has two sources on purpose: the class log (taught sessions, solid
  bars) and the course hub (decks ready, outlined bars). The hub is read from
  `logs/business_hub_index.html`; copy the live `index.html` over it whenever a
  new deck is published.
- `PLAN` and `VERDICTS` at the top of `build.py` hold the agreed monthly plan and
  the mentor's plan-vs-actual verdict. Extend them month by month.
- Test scores are not in any log yet. When the tutors report them, add a
  `scores.json` dataset (date, subject, assessment, score, max) and a card; the
  page structure already separates "content taught" from "results".

## Data files the page reads (`docs/data/`)

| file | one row per | key fields |
|---|---|---|
| `sessions.json` | logged session | date, week, subject, tutor, content, hours, kind, unit, unit_en/vi, recording |
| `weekly.json` | week × subject | week, subject, sessions, hours, topics, units |
| `syllabus.json` | exam topic | exam, unit, name_en/vi, weight, status, subtopics, subtopics_covered, subtopics_prepared, coverage, prepared |
| `materials.json` | Business deck | session, title, status (ready / coming_soon), units, file |
| `plan.json` | month × subject | planned_en/vi, actual_en/vi, verdict |
| `observations.json` | observation | type, subject, date, source, title/detail (vi, en), quote, response, status |
| `evaluation.json` | survey item | item_en/vi, score, max |
| `meta.json` | build | generated, subjects, warnings |
